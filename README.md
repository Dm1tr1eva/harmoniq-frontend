# 🧘 Harmoniq — Frontend

Фронтенд для Harmoniq — платформи для публікації статей про ментальне здоров'я, усвідомленість і внутрішню рівновагу. Побудований на Next.js 16 (App Router).

## Про проєкт

Harmoniq об'єднує людей навколо теми ментального благополуччя: автори публікують статті про усвідомленість, роботу з тривогою, відновлення ресурсу й побудову здорових звичок, а читачі знаходять серед них своє — переглядають популярні матеріали, читають профілі авторів, зберігають статті у власний список і повертаються за новими текстами. Цей репозиторій — клієнтська частина: усі сторінки, форми і взаємодія з користувачем, а також внутрішній BFF-шар (`app/api/**`), через який проходять усі запити до бекенду.

Це командний навчальний проєкт (капстоун GoIT), написаний з нуля за технічним завданням і дизайн-макетом: семантична адаптивна верстка на трьох переломах, розмежування публічних і приватних маршрутів, кешування запитів, форми з валідацією.

Бекенд, який обслуговує це API: [harmoniq-backend](https://github.com/Dm1tr1eva/harmoniq-backend) (Node.js + Express + MongoDB).

## Функціонал

- Реєстрація та вхід з валідацією форм (Formik + Yup), завантаження аватара після реєстрації
- Головна сторінка: популярні статті, топ авторів, розповідь про проєкт
- Стрічка статей з фільтрами (Popular / All), пагінацією і лічильником
- Сторінка статті: повний текст, рекомендації "You may also like", збереження в закладки
- Сторінки авторів: список і профіль з переліком статей
- Приватний профіль користувача: вкладки "Мої статті" / "Збережені статті" через паралельні роути
- Створення статті з завантаженням зображення
- Розмежування публічних і приватних маршрутів на рівні middleware, тихе оновлення сесії
- Лоадери на рівні сторінки і на рівні окремих запитів, обробка помилок через toast-нотифікації
- Усі запити до бекенду йдуть через внутрішні Route Handler'и (`app/api/**`), адреса бекенду ніколи не потрапляє в клієнтський бандл

## Стек

- Next.js 16 (App Router), **TypeScript**
- CSS Modules (без Tailwind), `modern-normalize`
- Mobile-first, брейкпоінти: 320px / 375px / 768px / 1440px
- Zustand (стан), TanStack Query (запити) — провайдер вже підключений у `layout.tsx`
- Formik + Yup (форми) — переюзабельні валідаційні схеми лежать у `lib/validation`
- ESLint + Prettier

## Швидкий старт

1. Встановити залежності:

   ```bash
   npm install
   ```

2. Скопіювати `.env.example` в `.env` і заповнити значення (опис — у таблиці нижче):

   ```bash
   cp .env.example .env
   ```

3. Запустити у dev-режимі:

   ```bash
   npm run dev
   ```

Фронтенд підніметься на `http://localhost:3001`.

⚠️ Бекенд ([harmoniq-backend](https://github.com/Dm1tr1eva/harmoniq-backend)) за замовчуванням теж слухає порт 3000 — тому фронтенд навмисно переключений на **3001** (`next dev -p 3001` в `package.json`), щоб можна було запускати обидва одночасно. Бекенд треба піднімати окремо (`npm run dev` в його репозиторії).

## Змінні оточення

| Змінна                | Опис                                                                       |
| ---------------------- | ----------------------------------------------------------------------------- |
| `API_URL` | Адреса бекенду (`http://localhost:3000` локально, реальний URL — на проді). Без `NEXT_PUBLIC_` навмисно: `api.ts`/`proxyRequest.ts` виконуються лише на сервері, і цей префікс інлайнив би адресу бекенду в клієнтський бандл, ламаючи сенс BFF-проксі |
| `SITE_URL` | Публічна адреса фронтенду (`http://localhost:3001` локально). Потрібна для абсолютних URL у прев'ю посилань (`og:image`, `og:url`); якщо не задана — береться прод-адреса на Vercel |

## Структура проєкту

```
src/
  proxy.ts           — гейт приватних роутів + BFF-проксі; єдине місце, де
                       перевіряється сесія перед рендером сторінки
  app/               — сторінки (Next.js App Router, файлова маршрутизація)
    (auth)/          — публічні сторінки логіну/реєстрації (route group)
    (private)/       — сторінки, доступні лише авторизованим (route group)
    api/             — Route Handler'и, реальні проксі до бекенду через lib/api/proxyRequest.ts
  components/        — переюзабельні компоненти, по папці на компонент
  lib/
    api/             — axios-інстанс + типізовані функції під кожен ендпоінт бекенду
    store/           — Zustand-стори
    validation/      — переюзабельні Yup-схеми (наприклад, `authSchemas`)
  styles/            — глобальні стилі (`reset.css`, `base.css`, `container.css`)
  types/             — доменні типи (`User`, `Article` тощо)
```

## Як додати нову сторінку/компонент

1. **Сторінка** — вже створена заглушка в `app/<route>/page.tsx` (структура маршрутів відповідає ТЗ). Просто пиши логіку в готовий файл.
2. **Компонент** — заглушка в `components/<Name>/<Name>.tsx`. Поруч уже лежить порожній `<Name>.module.css` — просто пиши стилі туди й підключай `import styles from "./<Name>.module.css"`.

Кожна сторінка/компонент — окрема папка й окремий файл, тому паралельна робота декількох людей не призводить до конфліктів при мерджі.
